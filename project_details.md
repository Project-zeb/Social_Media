## Technical Documentation: SurgeGuard AI Disaster Management System

### Project Overview
SurgeGuard AI is an industry-grade, Human-in-the-Loop (HITL) disaster management platform designed to ingest, triage, and verify emergency-related data from social media feeds in real-time. The system utilizes multimodal AI models to filter noise and prioritize critical incidents for human officers.

---

### 1. Core Architecture and Logic

#### Trust Hierarchy (Intel Tiers)
The system operates on a four-tier authority model to ensure data integrity:
* **Tier 3 (Official Verified)**: Manually vetted by an authorized officer. This status overrides all AI scores and sets the truth score to 100%.
* **Tier 2 (AI Validated)**: High-confidence reports that have passed the multimodal AI triage but lack human confirmation. These are capped at a maximum of 99% confidence.
* **Tier 1 (Pending/Flagged)**: Raw reports or items where the AI detected a potential mismatch or low confidence.
* **Tier 0 (Fake/Dismissed)**: Reports explicitly marked as malicious or incorrect by an officer.



#### Mathematical Formulas
The platform uses two primary formulas for data prioritization and lifecycle management:

**1. Multimodal Triage Score (OpenAI CLIP)**
The initial confidence score is generated by calculating the cosine similarity between the translated English text and the associated image:
$$Score = \cos(\theta) = \frac{A \cdot B}{\|A\| \|B\|}$$
Where $A$ is the text vector and $B$ is the image vector.

**2. Temporal Decay Formula**
To ensure the dashboard remains current, a decay function is applied to the truth score every hour. This simulates the diminishing relevance of older reports:
$$DisplayScore = TruthScore \times (0.92^{hours\_passed})$$
If the $DisplayScore$ drops to 0.1 or less, the incident is automatically removed from the public Live Feed but remains in the administrative archive.

### 2. Implementation Modules

#### Multilingual Triage Engine
The system ingests raw text (supporting Hindi and English) and processes it as follows:
1.  **Translation**: Uses the Helsinki-NLP (MarianMT) model to translate non-English text into English.
2.  **Verification**: Uses OpenAI CLIP to compare the text summary with the provided image.
3.  **Classification**: If the CLIP score exceeds 22.0, the event is promoted to HIGH_PRIORITY (Tier 2); otherwise, it is FLAGGED (Tier 1).

#### Human-in-the-Loop (HITL) Control
* **Verify**: Allows an authenticated officer to promote an incident to Tier 3, setting the truth score to 100% and recording the specific officer's identity.
* **Undo (Restore)**: An intelligent reset button. If an officer undoes a verification, the system checks the original AI triage score. If that score was $\ge 22.0$, the item returns to AI Verified; otherwise, it returns to Pending.

### 3. Setup and Execution

#### Environment Configuration
Sensitive credentials must be stored in a .env file. Key variables include:
* `SECRET_KEY`: Django security key.
* `DATABASE_URL`: Connection string for the database.
* `TRANSLATION_MODEL`: Path to the local or HuggingFace translation model.
* `INGESTION_INTERVAL`: Frequency of the mock feed ingestion.

#### Running the System
To operate the platform with real-time WebSocket updates and the background task queue, execute the following commands in separate terminal windows:

**1. Start the Task Worker (Dragonfly/Celery)**
Processes the AI triage in the background:
```bash
celery -A sg_intel worker --loglevel=info
```

**2. Start the WebSocket and Web Server (Daphne)**
Handles real-time live feed updates:
```bash
daphne -b 0.0.0.0 -p 8000 sg_intel.asgi:application
```

**3. Start the Production Mock Feed**
Simulates the ingestion of social media data:
```bash
python manage.py run_mock_feed
```

**4. Start the Decay Engine**
Maintains the relevance of the truth scores:
```bash
python manage.py apply_decay
```

---

### 4. Administrative Security
* **Role-Based Access Control (RBAC)**: Non-authenticated users can only view the Live Feed (Tiers 2 and 3). Administrative actions, including Verify, Fake, and Undo, are strictly restricted to logged-in officers.
* **Accountability**: Every official verification is logged via the `verified_by` ForeignKey, ensuring a clear audit trail for every Tier 3 decision.
